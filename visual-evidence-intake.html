3. Architectural best practices & publication gate

Provenance required

Capture ID; source repository and commit; original filename and cryptographic digest; instance alias; application sys_id, scope and version; capture date; persona; test case; actual result; evidence classification; reviewer and publication decision.

Sanitisation required

Remove names, emails, domains, record IDs that identify clients, tokens, customer branding, personal data, operational findings and browser session information. Review the final rendered pixels and metadata, not just the filename.

Runtime classification

SOURCE-ONLY: code or documentation exists. MOCK-ONLY: simulated interface. DEV-VERIFIED: independently executed test on identified DEV build. PRODUCTION-VERIFIED: separately approved production evidence. Historic repository assertions are not new independent verification.

Release gate

Keep originals in restricted storage. Publish only a separate sanitised derivative after provenance, confidentiality and reviewer approval. Record the public asset path and approval in the evidence register. Revoke publication if a defect or disclosure is found.
