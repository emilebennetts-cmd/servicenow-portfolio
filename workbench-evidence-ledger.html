Verification boundary

SOURCE-ONLY

Repository files and documentation support design and implementation claims, but do not prove successful installation, execution or end-user acceptance.

DEV-VERIFIED

Only a dated, attributable DEV execution or read-back record supports this label. Historical claims remain historical; a newer source version is not automatically verified.

MOCK-ONLY

Illustrative screens, synthetic fixtures and conceptual diagrams are explanatory, not evidence of native platform behaviour.

PRODUCTION-VERIFIED

Not established for the Workbench functionality described here. Production proof requires approved, independently reviewable execution evidence.

Technical review checklist

  • Confirm application scope and version in the target instance, not from the repository version alone.
  • Execute role-based smoke tests and verify read-only collector behaviour and evidence lineage.
  • Validate pattern selection, approval gates, draft reconciliation and no-duplicate generation.
  • Test optional external integrations with approved credentials, replay/error handling and least privilege.
  • Attach attributable DEV or production test receipts before promoting a verification label.
