01 · The client's pain & history

Healthy-looking numbers can conceal missing evidence.

In this representative client scenario, a legacy ServiceNow estate runs multiple collectors across partially licensed products. A table is unavailable in one environment, a grouped query reaches its cap in another, and a third export arrives without its complete wrapper. Treating all three as successful zero findings would undermine the entire assessment. This is an illustrative consulting problem, not a customer incident claim.

Unclear applicability

Unavailable product tables should be recorded as Not Applicable, never silently counted as zero.

Unreliable denominator

Truncated aggregations distort scorecards, ageing ratios and impact estimates even when the payload parses.

Ungoverned authority

Passing a parser does not establish collection permission, privacy compliance, reviewer approval or fitness for delivery.

02 · The ServiceNow solution

Source-traced envelope assurance. No hidden execution.

The Diagnostic Workbench 2 source catalogue declares DIAG_ENVELOPE_BEGIN and DIAG_ENVELOPE_END, a schema_version, read_only, contains_pii, aggregate metrics, result groups and a notes channel. Its ITSM Incident collector sets record_count to the length of the results array, not the incident-table total. This lab models an intentionally conservative subset of that contract. It does not replicate the private application's complete validation engine or run scripts in ServiceNow.

What the review still needs

    Source semantics and data safety: In the source collector, record_count counts emitted aggregate-group rows, whereas metrics.total counts incidents. A zero result-group count therefore is not a zero-incident population. This deliberately restrictive illustrative model rejects unexpected fields, free-text group values and incompatible count shapes; it cannot certify or parse arbitrary native envelopes.

    Privacy and permission boundary: The selector uses only fabricated in-code fixtures. There is no upload, paste, API call, instance connection or persistent browser storage. Do not submit real ServiceNow output to this public demonstration. Running read-only Scripts – Background collectors still requires explicit platform approval and an assessed execution impact.

    03 · Architectural best practices

    OOTB-first, least privilege, honest proof.

    Read-only is not risk-free

    Prefer native role-controlled read and aggregate APIs; assess large-table query cost, index use, group caps and access in DEV before any approved production run.

    Separate identities

    The original Diagnostic module-pack DIAG envelope is distinct from the Knowledge Intelligence companion's KI-EVIDENCE format. No interchangeability, adapter or native interoperability is asserted.

    Trace to human acceptance

    ITIL 4 continual improvement demands reproducible evidence and accountable decisions. Candidate findings stay draft until owners verify population, root cause, impact and delivery authority.

    Licensing and entitlements: The static website requires no ServiceNow licence. Real collector execution requires approved script authority, correct roles and custom-app hosting rights where applicable; ITSM, ITOM Visibility/Discovery, SecOps, IRM, CSM, HRSD, ITAM/HAM/SAM, IntegrationHub and analytic capabilities must be checked against installed products and contracts. No entitlement is inferred from source presence.

    Evidence boundary: SOURCE-ONLY model based on private Diagnostic Workbench 2 catalogue and historical documentation; all interactive examples MOCK-ONLY. No newly DEV-VERIFIED or PRODUCTION-VERIFIED outcomes and no approved genuine screenshots. Existing source/DEV historical reports remain date-bounded.
