01 / The client's pain & history

In a typical mature ServiceNow estate, consultants inherit inconsistent configuration documentation, uncertain data quality and scattered operational evidence. Unreviewed diagnostic scripts can add risk, while findings without traceable source metrics are difficult to defend. This is a representative consulting problem, not a measured claim about a named customer.

02 / The ServiceNow solution

The public Diagnostic Workbench 2 repository documents a scoped application and a separately deployed Knowledge Intelligence companion. Its documented chain connects governed knowledge sources, symptoms and discovery questions to read-only collectors, evidence records, rules, findings awaiting review and solution patterns.

03 / Architectural best practices

Prefer OOTB reporting and supported read APIs where practical; constrain scoped app roles and ACLs, keep client data within approved boundaries, review script permissions and retain reproducible evidence. A read-only design does not itself establish that running scripts is authorised. Follow ITIL 4 continual improvement principles, segregate DEV from production verification and version deployment artefacts through controlled change.
