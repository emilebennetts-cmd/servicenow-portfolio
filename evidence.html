Evidence classification

What each claim can actually establish

SOURCE-ONLY

Inspected implementation

Repository code, tests, model and version declarations can support a source implementation claim. A commit does not prove installation, access control or a passing native workflow.

Historical DEV-VERIFIED

Time- and version-scoped read-back

A dated, reviewed instance observation can substantiate the observed version and objects at that time only. It cannot certify later source changes, current DEV state or Production.

MOCK-ONLY

Illustrative experiences

Examples, demonstrations, synthetic findings, CSS diagrams and test fixtures explain intended behaviour without representing a real customer's environment or executed acceptance.

What a genuine DEV screenshot could prove

A capture may corroborate that a particular interface was displayed at a stated time. It cannot independently prove a deployed source SHA, backend persistence, permissions, correct data processing, UAT or Production acceptance.

How an image becomes publishable

Capture provenance and ownership; perform irreversible redaction; export a clean derivative; inspect pixels and embedded metadata; retain a cryptographic digest; record image-specific independent reviewer approval in private custody; only then update the public approval manifest.
