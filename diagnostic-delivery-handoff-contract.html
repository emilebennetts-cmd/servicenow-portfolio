1. The client's pain & history

Uncontrolled data movement

Teams often copy diagnostic outputs into workshop packs without a recorded collection scope or review. Sensitive values and unknown lineage can travel with a seemingly helpful finding.

Competing systems of record

A new delivery workspace can accidentally become a second writable evidence store. Duplicated findings then diverge from the operational assessment and change without a clear owner.

Evidence confused with approval

A source commit, synthetic scenario or dated developer test report may be treated as proof of current-instance operation. Environment identity, licences and release authority are then overlooked.

3. Architectural best practices

OOTB-first, scoped by role

Use supported roles, ACLs, update-set or SDK promotion and native approvals where available. Test the exact instance, installed app identity and package version before accepting a custom-scoped design.

Single ownership of evidence

Persist original operational evidence and findings in Diagnostic's authorised store. Delivery stores immutable references and independent handoff/acceptance status; do not silently copy confidential evidence into workshop records.

No automatic certification

Collector lint, source builds, browser simulations and historical DEV read-backs prove different things. Native DEV acceptance requires dated actor, target, outcome and independently reviewable private evidence; production is a separate gate.

Documented source basis and limitations

Source reviewed: the Universal Delivery Workbench repository README (source 4.22.2), Diagnostic Workbench 2 README and Knowledge Intelligence 0.1.0 README, plus the controlled portfolio release history. Knowledge Intelligence is a separately installed companion with governed evidence intake; it is not asserted to be automatically navigable from or synchronised with the core Workbench.

Illustrative native acceptance checks

Negative collector mutation tests; redacted evidence-envelope validation; no healthy score for an unassessed area; link from rule to metric to reviewed finding; source-and-target identity match; role-negative ACL tests; delivery reference and version integrity; independent operational owner approval and change control.
