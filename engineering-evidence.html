What the source proves — and what it does not

An inspectable register of application evidence, verification gaps and release boundaries. The portfolio deliberately separates repository implementation, historical DEV reports, illustrative interfaces and independently observed runtime behaviour.

New for technical reviewers: Follow the source-traced Diagnostic → Delivery walkthrough, including implementation evidence, verification gaps and licensing boundaries.

Evidence classification

Source-only

Repository code or documentation supports an implementation claim. This does not prove the feature was installed, executed or accepted in an instance.

Historical DEV-reported

Prior test notes or release documents describe DEV execution. Treat as dated, version-specific reporting until reproduced independently.

Mock-only

Static or interactive portfolio illustrations explain a workflow. They are not captured ServiceNow application screens or operational evidence.

DEV-verified / Production-verified

Reserved for independently observed execution with environment, build, timestamp, test evidence and reviewer. Neither status is asserted by this register.

Genuine screenshot publication gate

No unreviewed images are presented as real application captures here. The screenshot gallery remains pending. Private client information, credentials, instance addresses, internal IDs and identifying records must not be exposed.

  1. Retain original capture and private provenance: application, version, instance type, capture date and authorised reviewer.
  2. Inspect all visible UI text, browser chrome, tooltips and metadata; redact confidential or identifying content in a derivative copy.
  3. Obtain explicit publication approval for the exact derivative, and record its SHA-256 digest.
  4. Publish only the approved immutable derivative with an accurate caption and SOURCE / DEV / PRODUCTION classification; never imply production verification from a DEV capture.
  5. Re-run publication integrity and secret checks on every replacement.

See screenshot approval policy.

Licensing and entitlement boundaries

The public static website requires no ServiceNow licence. Running the scoped applications requires an authorised instance, appropriate user roles and confirmation of custom application entitlement. ITOM capabilities, IntegrationHub spokes, Performance Analytics, AI features and third-party provider subscriptions may require separate licences or approvals; none are assumed included.
