Evidence governance · 6 November 2026

Claims you can trace. Boundaries you can trust.

A transparent standard for distinguishing a repository feature, a simulated demonstration, a tested DEV implementation and an independently verified production outcome.

Publication policy: No customer-identifying evidence, private source, secrets or unapproved screenshots. A repository assertion is not a runtime verification.

01 · The client's pain & history

Engineering portfolios can unintentionally conflate screenshots, design intent, code presence and operational deployment. That ambiguity undermines technical due diligence and can disclose sensitive instance data. This portfolio uses a claim-by-claim evidence boundary rather than treating all demonstrations as production outcomes.

02 · The ServiceNow solution

Source-only

A public repository file, documented configuration or source export supports the described design or implementation. It does not prove installation, correct execution or user acceptance.

Mock-only

Sample records, simulated providers and illustrative interfaces demonstrate an interaction. They must not be represented as live Jira, Confluence, Notion or ServiceNow integrations.

DEV-verified

Requires an authorised instance, identified application version, reproducible test procedure, observed result, date and evidence reviewer. A README claiming DEV success is labelled DEV-reported until independently checked.

Production-verified

Requires authorised production deployment/change evidence, post-deployment checks and permitted, sanitised outcome evidence. None is currently independently established for these showcased applications.

03 · Architectural best practices

Prefer out-of-the-box capabilities, upgrade-safe scoped configuration, least-privilege access, repeatable test evidence, controlled change enablement and ITIL 4-aligned operational handover. Keep source evidence and runtime evidence separately versioned; do not publish instance identifiers or screenshots by default.

Entitlements: This static site has no ServiceNow licensing requirement. Custom scoped application installation and any ITSM, ITOM, ITAM, IRM, HRSD, CSM, SecOps, IntegrationHub, AI or analytics capability require target-instance entitlement checks. External providers may require their own licences and API permissions.
