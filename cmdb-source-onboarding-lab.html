01 / The client's pain & history

Three imports, three different versions of the same server

A representative enterprise accumulates cloud inventory, endpoint-management records and network discovery. Names collide, source identifiers disappear in mappings and low-confidence updates overwrite higher-quality attributes. Teams are left triaging duplicate CIs, unknown owners and unexplained reconciliation outcomes. This is an illustrative operating scenario, not a measured customer incident.

Identity

Name is not enough

Hostnames, IP addresses and short-lived instances are poor universal identifiers. Class-specific rules and dependent relationships need deliberate design.

Authority

Source precedence drifts

Without attribute-specific reconciliation and freshness rules, competing connectors can overwrite one another.

Assurance

Green dashboards can mislead

A successful import count does not prove IRE matches, completeness, correct relationships or business ownership.

03 / Architectural best practices
The minimum target validation matrix


TestExpected proof from a real ServiceNow environmentFailure condition


Known CI updateIdentification Simulation matches the expected class/record with a complete permitted payload; record IDs stay private.Unexpected insertion, skipped dependency or ambiguous identifier.


Missing strong identifierMissing key produces an explicit incomplete/rejected/partial outcome as determined by native IRE and configured rules.Automatically accepting a duplicate solely from the sample browser model.


Competing source attributeReconciliation Rule Preview and a controlled no-commit test demonstrate actual authority and priority for each field.Lower-authority source replaces protected value unexpectedly.


Freshness and nullTarget data refresh and null-update controls act according to configured class/attribute rules.Unreviewed null overwrite or unjustified stale record claim.


Security and scaleConnector ACLs, insert restrictions, batching, data classification and throughput measured in an authorised test instance.Unauthorised write, PII leakage or unbounded expensive collector.


Operational acceptanceCMDB Health baseline, duplicate-task routing, ownership and rollout/backout evidence recorded and approved.Import success mistaken for CMDB completeness or production sign-off.




Use OOTB Identification/Reconciliation definitions, IRE data-source rules, dependent-identification rules, CMDB Health and a governed connector path before considering custom write logic. Reconciliation is attribute-scoped and may combine static, dynamic and data-refresh conditions; this page does not attempt to reproduce that engine.
