01 / The client's pain & history

Consulting teams repeatedly reconstruct the same discovery, design, testing and handover material. An existing pattern library can still fail when definitions overlap, quality varies, provenance is lost or consultants mistake candidates for certified and installable solutions. The source review found duplicate concepts, thin descriptions and a need to separate catalogue coverage from target-instance availability.

That history motivated a governed authoring package with canonical decisions, deterministic offline validation and a controlled pilot-load requirement.

03 / Architectural best practices

OOTB-first

Confirm activation paths and supported platform features first. Justify each customisation; no generated pattern may assert a customer subscription or plugin identity without release-specific inspection.

Deterministic upgrades

Keep canonical JSON, generated artefacts and schema mapping under source control; validate stable keys, coalesce and rollback. Avoid direct edits to generated transport and protect upgrade-safe ownership boundaries.

Governed execution

Require named owners, role/ACL checks, release baselines, DEV test evidence and approval before importing patterns or automating customer configuration. Source QA never substitutes for native acceptance.
