02 / The ServiceNow solution

Govern the entire evidence chain

03 / Architectural best practices

OOTB, least privilege, upgrade safety

Prefer ITIL-aligned native capabilities, documented scope boundaries and supported platform APIs. Require owner approval and target-instance acceptance rather than inferring deployment from source, package builds, UI mock-ups or historical documents.

ADR-01EVIDENCESOURCE-DERIVED · NOT APPROVED

One owner for operational findings

Design choiceDiagnostic Workbench owns investigation records, editable evidence and findings. Delivery Workbench consumes governed references and reviewed handoff outcomes rather than creating a second writable evidence store.

Rejected shortcut
Duplicate findings into Delivery for convenience.
Risk controlled
Divergent dispositions, lost source provenance and uncertain accountability.
Native acceptance gate
Witness a finding lifecycle, reviewer decision, reference integrity and a denied unauthorised write in the target instance.

ADR-02SECURITYSOURCE-DERIVED · NOT APPROVED

Zero-footprint before instance access

Design choiceStart with client-neutral assessment, supplied artefacts and explicitly labelled proposals. Native read-only collection requires authority, appropriate roles, bounded queries and a suitable non-production target.

Rejected shortcut
Run broad diagnostic scripts on the customer instance during initial discovery.
Risk controlled
Unapproved execution, excess data access or misleading completeness when a collector is not run.
Native acceptance gate
Record permission, roles and execution context; prove query caps and read-only operation; classify missing evidence as not assessed.

ADR-03DELIVERYSOURCE-DERIVED · NOT APPROVED

OOTB-first, upgrade-aware delivery

Design choicePrioritise native process capabilities and supported APIs, then reviewed reusable patterns. Require explicit design rationale before custom tables, roles, scripts or cross-scope access.

Rejected shortcut
Deploy a catalogue pattern as a universally valid client configuration.
Risk controlled
Licensing mismatch, upgrade fragility and false assumptions about a customer's baseline.
Native acceptance gate
Capture product release and subscription, confirm applicable OOTB behaviour, obtain architecture approval and test protected upgrade paths.
Review pattern governance ↗
ADR-04SECURITYSOURCE-DERIVED · NOT APPROVED

Protect package and application identity

Design choiceTreat technical scope, package version and trusted artefact digest as separate checks. Compare against the actual target application, and require independent installation and behaviour read-back.

Rejected shortcut
Accept a matching display name or visual UI as deployment proof.
Risk controlled
Wrong-scope overwrite, stale packages and false release acceptance.
Native acceptance gate
Reconcile target scope, version, trusted checksum, package identity, UI Page, ACLs and attributable native evidence.
Inspect release reconciliation ↗
ADR-05INTEGRATIONSOURCE-DERIVED · NOT APPROVED

External writes default to disabled

Design choiceKeep work-provider synchronisation and AI/external transport gated by explicit consent, validated credential aliases, approved endpoint contracts and failure controls. Local demonstration is not external integration.

Rejected shortcut
Enable a connector because a UI control or mock workflow exists.
Risk controlled
Unapproved data egress, silent conflict resolution or inconsistent system of record.
Native acceptance gate
Verify provider access and commercial entitlement, credential ownership, replay behaviour, audit, revocation and failure handling.
Review integration contract lab ↗
ADR-06DELIVERYSOURCE-DERIVED · NOT APPROVED

Generated documents are drafts, not approvals

Design choiceUse governed templates and traceable source data to assemble SOWs, design packs and handover artefacts. Independent review and business sign-off remain separate lifecycle gates.

Rejected shortcut
Mark an engagement approved because a document file was generated.
Risk controlled
Uncontrolled commitments, missing signatories and no source-to-artifact lineage.
Native acceptance gate
Read back template version, inputs, attachment integrity, approval workflow and accountable decision before promotion.

ADR-07INTEGRATIONSOURCE-DERIVED · NOT APPROVED

Human review of AI-assisted recommendations

Design choiceBound AI-assisted drafting to selected, minimised data and distinguish a suggested action from an approved configuration, finding or business decision.

Rejected shortcut
Automatically execute model recommendations on live scoped data.
Risk controlled
Unreviewed errors, confidential context disclosure and unaudited configuration mutation.
Native acceptance gate
Check feature availability, licensed connectors, consent, data minimisation, human approval, audit trail and kill switch.
Inspect implementation boundaries ↗
ADR-08EVIDENCESOURCE-DERIVED · NOT APPROVED

Provenance outranks visual similarity

Design choiceClassify source implementation, historical DEV reporting, independently witnessed current DEV behaviour, mock demonstrations and verified Production outcomes separately. Real screenshots require per-image sanitisation and release approval.

Rejected shortcut
Present attractive mock screens or historical read-backs as current production proof.
Risk controlled
Misleading portfolio claims and accidental publication of customer or platform information.
Native acceptance gate
Link each public claim to attributable dated evidence; independently test native functionality; approve any screenshot individually.
