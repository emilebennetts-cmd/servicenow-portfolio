04 / Independent DEV acceptance choreography

Run the source checks in a defensible dependency order.

This illustrative review sequence helps a technical consultant organise the 117 existing native checks. It is not an execution engine or ServiceNow processing order. Each stage remains HOLD until current target configuration, authorised synthetic sampling, negative-role tests and independent evidence receipts are captured outside the public site.

Entry gate — no native test is certified

Before stage one, obtain written non-production authorisation; record exact instance, installed scope/release and plugins; confirm subscription entitlements; approve synthetic source and CI samples; provision positive and denied-access personas; and nominate an independent reviewer. These are prerequisites, not extra counted acceptance tests.

  1. STAGE 1 · 18 CONTROLS · HOLDCI identity and IRE precedence

    Inspect identification/reconciliation rules, stable keys, replay behaviour and negative-persona access.

    Exit: Accepted matching, collision and replay evidence before assessing dependent metadata.

  2. STAGE 2 · 25 CONTROLS · HOLDTag governance and attribution

    Validate key conventions, cost ownership, value authority and source-level repair.

    Exit: The same source replay no longer restores the bad tag.

  3. STAGE 3 · 24 CONTROLS · HOLDCMDB Health score lineage

    Capture effective jobs, rules, cohort eligibility, freshness and comparable denominators.

    Exit: Independent reviewer reconciles job completion and comparable CI populations.

  4. STAGE 4 · 30 CONTROLS · HOLDRelationship integrity

    Review effective CI Class Manager rules and topology against source-system evidence.

    Exit: Duplicate, orphan, invalid-direction and denied-role scenarios reviewed.

  5. STAGE 5 · 20 CONTROLS · HOLDControlled lifecycle and attestation

    Check source re-ingestion, exclusions, retention/legal holds, approvals and rollback.

    Exit: Independent approver confirms sampled policy effects and recovery evidence.

Stage dependencies are a proposed audit workflow. Real environments may run tests in parallel when their prerequisites are proven. No stage automatically authorises the next or changes native records.

05 / Local-only evidence preflight

Inspect the acceptance receipt. Never mistake completeness for certification.

Use the full 117-control workpack, edit a sanitised copy offline, then inspect that CSV here. This tool checks source-controlled IDs, review stages, status boundaries and the shape of candidate DEV receipt metadata. It cannot establish that a ServiceNow instance, evidence reference, test, approval or independent reviewer is genuine.

Confidentiality and claim boundary

Inspect only a redacted or synthetic copy. Keep customer CI identifiers, email addresses, secrets, screenshots, instance URLs and underlying evidence in approved private storage. The CSV is read in this browser only: no upload, outbound connection, local storage or retained source rows. A passing format check is not a DEV-VERIFIED, PRODUCTION-VERIFIED or release GO decision.

Unrun rows stay NOT RUN / HOLD / MOCK-ONLY. When a controlled non-production execution is reported, use PASS, FAIL or BLOCKED with DEV-REPORTED, HOLD, an opaque private receipt ID, a target alias, installed version, UTC timestamp and distinct executor/reviewer aliases. Never put actual private evidence or credentials in the CSV.

    06 / Architectural best practices

    Native governance, not a parallel custom engine.

    OOTB-first

    Use installed IRE, native CMDB Health, CI Class Manager effective rules, Tag Governance and Data Manager; this website does not reproduce the native algorithms.

    Source authority

    Verify payload provenance, rule revision, population lineage, positive and negative roles, replay after source correction and independent evidence receipts.

    Safe delivery

    Stage representative non-production tests, avoid indiscriminate CI deletion, review processor performance, protect client identifiers and obtain independent sign-off.
