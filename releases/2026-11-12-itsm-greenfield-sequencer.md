# ITSM Greenfield Build Sequencer — public release
Date: 12 November 2026

## Client pain and implementation value
Generic greenfield ITSM delivery often starts with disconnected workshops, premature configuration and test designs mislabelled as actual execution. This release introduces a customer-neutral, OOTB-first implementation sequence with traceable acceptance control. The representative story is illustrative, not a named-customer performance claim.

## Source review and scope
Reviewed the private Solution Lifecycle Studio implementation-pack library README (0.1.0-demo, dated 7 October 2026), its phases.json and Incident Management candidate specification. The source states nine candidate ITSM packs, baseline-to-assurance delivery phases, documented native scope boundaries and strict limitations on deployment and existing Delivery engine integration. Public authorship is independent: no private pack content or code reproduced. Consulted Diagnostic Workbench source portfolio narrative for separate collector/evidence versus delivery authority.

## Actual change
- Added itsm-greenfield-build-sequencer.html with nine customer-neutral capability families, nine delivery phases, OOTB configuration, positive and negative test designs.
- Interactive capability selector, eight synthetic governance controls and three scenarios (complete, access/entitlement gap, test/handover gap).
- Deterministic JSON receipt explicitly denies DEV execution, production deployment, customer authorisation and release identity.
- Responsive layout and keyboard focus, source/DEV/PROD/mock boundaries, private screenshot hold, conditional licensing.
- Added automated static contract and Chromium browser regression; integrated public portfolio navigation and sitemap.

## Verification boundaries
- SOURCE-ONLY: repository HTML, scripts, docs and test definitions; GitHub release to be checked separately.
- MOCK-ONLY: nine capability illustrations, gate checkbox states and all calculated receipts. Model completeness is not a test pass.
- DEV-VERIFIED: no fresh instance verification or ATF execution.
- PRODUCTION-VERIFIED: not established.
- Screenshots: no real image copied; all existing candidates remain HOLD pending image-specific authorisation, review and redaction.
- No repository visibility change, private implementation source, credentials or customer data published.

## Testing and licensing
Static checks: Python unittest, site quality/link audit and publication guard. Chromium: 390, 768, 1024, 1440 px scenario status, selector semantics, overflow, receipt integrity. Check actual workflow results and GitHub Pages deployment before claiming pass.
Static site: no ServiceNow licence. Live ITSM requires contractual core ITSM rights, roles and ACLs; optional ITSM premium, custom-app/App Engine, ITOM/Discovery, IntegrationHub, analytics, AI and third-party subscriptions require instance-specific licensing review.
