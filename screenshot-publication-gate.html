Verification rules
Source-only: a repository artefact or documentation is not a deployment test. DEV-verified: requires dated instance evidence, matching version and observable outcome. Mock: synthetic screens and simulated integrations must be labelled. Production-verified: requires independently supported production evidence and explicit publication authority. Do not infer deployment from a screenshot alone.
Automated publication boundary: public CI checks approved image hashes and common metadata markers, and blocks unreviewed image rendering paths including active HTML frames and embedded objects, SVG filter images, video posters, responsive srcset candidates, image preloads, CSS image-source selection functions, ambiguous duplicate image-control attributes, CSS image properties and social preview metadata (Open Graph, Twitter and legacy image links). Social crawlers are outside page CSP, so any preview must resolve to the same origin and an approved image SHA-256. These fail-closed checks do not inspect actual screenshot pixels or grant permission to publish. Review the source-only release and test controls.
Entitlements: this static review page requires no ServiceNow licence. Running scoped applications, ITSM/ITOM/IRM/CSM modules, IntegrationHub spokes, AI or advanced analytics requires the relevant target-instance entitlements and access rights.
