12 source-described procedures. Review marks are local to this open page only.

  1. USER GUIDE §4.1 · START

    Initialise an engagement

    Prerequisites: appropriate presales role, approved context and authorised non-Production target.

    Expected records: engagement, members, generated journey, audit history.

    Control: confirm role and engagement membership; leave AI processing undecided without authority.

  2. USER GUIDE §4.2 · SCOPE

    Capture outcomes, requirements and scope

    Prerequisites: sponsor input and engagement membership.

    Expected records: linked outcomes, decisions, scope objects, estimates and baselines.

    Control: unresolved parameters stay open; deferred scope requires authority and does not become delivered scope.

  3. USER GUIDE §4.3 · JOURNEY

    Inspect journey blockers

    Prerequisites: an initialised engagement and active membership.

    Expected records: journey readiness, linked evidence, decisions and waivers.

    Control: resolve blockers with evidence; never simply advance a status or bypass a gate.

  4. USER GUIDE §4.4 · DISCOVERY

    Run a controlled workshop

    Prerequisites: documented purpose, participants and scope.

    Expected records: workshop, attendance, parameter decisions and linked actions.

    Control: unresolved assumptions and RAID items remain explicit, not hidden in notes.

  5. USER GUIDE §4.5 · DESIGN

    Approve a build specification

    Prerequisites: approved requirements, resolved design and valid target components.

    Expected records: linked build specification, validation result and approver decision.

    Control: invalid tables and missing entitlements block execution; avoid self-approval.

  6. USER GUIDE §4.6 · IMPLEMENT

    Build, test and preserve evidence

    Prerequisites: approved non-deferred build and authorised target.

    Expected records: change/update-set reference, test result, defect and retest proof.

    Control: describe observed results; a design or test case is not a test pass.

  7. USER GUIDE §4.7 · DECISION

    Review approval or waiver

    Prerequisites: named, independent authority and supporting evidence.

    Expected records: approver, rationale, date, evidence, expiry if waived.

    Control: no response is not approval; waivers need expiry and remediation.

  8. USER GUIDE §4.8 · DOCUMENT

    Generate an approved-source artefact

    Prerequisites: approved template and complete bound source records.

    Expected records: versioned draft, source/template references and document review.

    Control: generated DOCX is not automatically approved; PDF output is feature-dependent.

  9. USER GUIDE §4.9 · DIAGNOSTIC

    Prepare a bounded read-only scan

    Prerequisites: current consent, read-only credential alias, allow-list and bounded scope.

    Expected records: scan run, limits, findings and calibrated review decisions.

    Control: stop on permission, consent or schema errors; do not broaden scope to force success.

  10. USER GUIDE §4.10 · AI

    Review AI-assisted design

    Prerequisites: explicit AI decision, approved bridge, alias and active kill-switch permission.

    Expected records: task, minimum disclosed context, proposal and human review.

    Control: no secrets or unapproved endpoints; AI output never self-approves.

  11. USER GUIDE §4.11 · RELEASE

    Prepare a governed non-Production release

    Prerequisites: approved build/tests, pinned commit and dedicated update set.

    Expected records: manifest, preview, installation result, version read-back, tests and approval.

    Control: unresolved preview errors are STOP; Production needs separate authorisation.

  12. USER GUIDE §4.12 · HANDOVER

    Seek operational acceptance

    Prerequisites: completed tests, approved as-built, support model and runbooks.

    Expected records: distinct business, technical, privacy and operations decisions.

    Control: record conditional or rejected acceptance; document creation does not close gates.
