1 · The client's pain & history

The inherited problem

Consultants inherit ServiceNow instances with uneven module adoption, custom tables that are poorly mapped to subscriptions, untested roles and integration assumptions embedded in proposals. A successful UI demo can be mistaken for a licensed, supported and deployable product.

The delivery consequence

Gaps surface during implementation: failed app installs, missing plugin rights, unsuitable production access or premium integration features outside the contract. Scope and target identity mismatches also invalidate otherwise credible source demonstrations. This is a representative consulting scenario, not a claim about any named customer.

3 · Architectural best practices

Prefer native ServiceNow capabilities, documented configuration and upgrade-safe extension points. Map custom tables to the authorised subscription, use ACL and negative-role testing, separate Tier-0/offline consulting from installed operations, and never equate CI or a simulated demo with deployment evidence.

Release decision: NOT VERIFIED / HOLD until a reviewer obtains a current contract interpretation, an approved target-instance inventory and independently witnessed acceptance. A licensed product is not automatically installed; an installed plugin is not automatically licensed. Approval of genuine screenshots is a separate, currently closed publication gate.
