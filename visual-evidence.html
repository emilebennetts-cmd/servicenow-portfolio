Evidence review workspace

Use this checklist for each candidate before replacing a placeholder with a real capture. A source file alone is not DEV verification.

  1. Confirm ownership, capture date, ServiceNow instance alias, application scope and version.
  2. Inspect original pixels for customer identifiers, personal information, internal URLs, tokens and proprietary scripts.
  3. Create a separate redacted derivative and inspect its pixels and metadata again.
  4. Record original and derivative SHA-256 digests, reviewer decision, permitted publication scope and evidence class.
  5. Publish only after explicit approval; otherwise keep the placeholder and mark the decision HOLD.

Protecting the publication boundary

A source-level CI rule now rejects embedded raster-image data URLs, unapproved remote image elements and SVG payloads that could conceal screenshot pixels. Standalone screenshot files still require reviewed, exact-byte SHA-256 approval. This is a technical safeguard, not proof that an image is safe or permission to publish it.

Publication status: genuine Workbench captures remain on HOLD. No image is released merely because automated checks pass. See the 13 November visual-asset control release note and the human publication review procedure.
