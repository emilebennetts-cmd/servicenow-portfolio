Verification discipline: None of these four reviews is DEV-VERIFIED or PRODUCTION-VERIFIED. The SOURCE-ONLY, MOCK-ONLY and document classifications describe evidence quality, not application performance. All originals remain private and unapproved.

Evidence review workspace

Use this checklist for each candidate before replacing a placeholder with a real capture. A source file alone is not DEV verification.

  1. Confirm ownership, capture date, ServiceNow instance alias, application scope and version.
  2. Inspect original pixels for customer identifiers, personal information, internal URLs, tokens and proprietary scripts.
  3. Create a separate redacted derivative and inspect its pixels and metadata again.
  4. Record original and derivative SHA-256 digests, reviewer decision, permitted publication scope and evidence class.
  5. Publish only after explicit approval; otherwise keep the placeholder and mark the decision HOLD.

Evidence pipeline

From private capture to credible case-study evidence

01 / Inspect

Read the image, identify actual UI elements, classify the application, and check for secrets, customer records and private instance information.

02 / Verify

Match the screen to the corresponding source release, DEV read-back or demonstration baseline. Mark any conceptual UI separately.

03 / Publish

Use a sanitized approved export with an accurate caption, source version and evidence status. Never expose private repository code or credentials.
